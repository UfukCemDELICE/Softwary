# Install, upgrade and uninstall

softwary is installed by copying files into your repository. Nothing is
installed on your machine outside it.

## What gets written

| Where | What | Who owns it |
| --- | --- | --- |
| `softwary` | A small wrapper that runs `.softwary/bin/softwary` | The package |
| `.softwary/bin`, `lib`, `rules`, `targets`, `skills`, `agents`, `hooks`, `templates`, `eval`, `VERSION` | The package | The package: overwritten on upgrade |
| `.softwary/config/` | `commands.conf`, `tools.conf`, `risk.conf`, `waivers.conf`, `loop.conf`, `models.conf`, `test-skip.conf` | Your project: written once, never overwritten |
| `.softwary/local/` | Your own skills, agents and targets, which override the package's | Your project |
| `.softwary/state/` | Jobs, the event log, logs; not committed | Your project |
| `AGENTS.md`, `CLAUDE.md`, `.claude/`, `.cursor/`, `.agents/`, `.codex/` | Generated by `./softwary sync` | Generated: commit them, do not edit them |

`install.sh` lists every file before it writes it. It never touches a file
called `softwary` that is not softwary's own wrapper, and it keeps the text of
an existing `AGENTS.md` or `CLAUDE.md` outside its own marked block.

## Install from a tag

```sh
git clone --branch v0.2.0 <softwary-repository-url> softwary
sh softwary/install.sh /path/to/your/repo
```

The target must be an existing directory. A git repository is expected; if it
is not one, `./softwary doctor` says so.

## Install from a release archive

A release has two files: `softwary-<version>.tar.gz` and `SHA256SUMS`. The
archive has one root directory, `softwary-<version>/`.

```sh
sha256sum -c SHA256SUMS                       # the download is the release
tar -xzf softwary-0.2.0.tar.gz                # to get install.sh
sh softwary-0.2.0/install.sh \
  --archive softwary-0.2.0.tar.gz \
  --sha256 <the digest in SHA256SUMS> \
  /path/to/your/repo
```

`install.sh` checks the SHA-256 before it opens the archive. It stops with
exit code 2, writing nothing, when the digest does not match, when `--sha256`
is missing, when the file is not a softwary package, or when it has more than
one root directory, a path that leaves the directory, or a link. It unpacks
into a temporary directory that it removes when it exits. On macOS, where
`sha256sum` may be missing, use `shasum -a 256 -c SHA256SUMS`.

## Upgrade

From a newer checkout or an unpacked archive:

```sh
./softwary upgrade /path/to/newer/softwary
```

From a release archive, with its digest:

```sh
./softwary upgrade softwary-0.2.0.tar.gz --sha256 <digest>
```

`upgrade` replaces the managed files, removes the managed files the new version
no longer has, and runs `./softwary sync`. It leaves `.softwary/config/`,
`.softwary/local/`, `.softwary/state/` and your own files alone. It prints
`upgrade: <old> -> <new>` first, re-applies the same version, and refuses to go
to an older one (exit code 2). `upgrade` does not edit your CI workflow; if it
needs a change, `upgrade` says which.

An installation older than 0.1.0 does not know `upgrade <archive>`. Upgrade it
with the installer of the new version instead:

```sh
sh softwary-0.2.0/install.sh --archive softwary-0.2.0.tar.gz \
  --sha256 <digest> /path/to/your/repo --upgrade
```

## Version

```sh
./softwary version     # softwary 0.1.0
```

## Uninstall

```sh
./softwary uninstall          # lists every path, writes nothing
./softwary uninstall --yes    # removes them
```

It removes the package: the managed files, the wrapper, the files and blocks
`sync` generated and `core.hooksPath` when it points at the package's hooks.
It keeps `.softwary/config/`, `.softwary/local/`, `.softwary/state/`,
`product/`, `architecture/`, `specs/`, `CONTEXT.md` and everything else of your
project, including the text of `AGENTS.md` outside the generated block. A
generated file you edited by hand is kept and listed as such. It stops (exit
code 1) while a run is open or a job is not finished.

## Making a release (for maintainers)

```sh
sh tools/release.sh 0.1.0
```

It requires `VERSION` to be `0.1.0`, a `## 0.1.0` section with content in
`CHANGELOG.md` and a clean working tree. It writes
`dist/softwary-0.2.0.tar.gz` and `dist/SHA256SUMS` from the current commit; two
runs on the same commit give the same bytes. It makes no tag, does not push
and uploads nothing. Tagging the commit, publishing the release and attaching
the two files are yours to do.
